🎯 Workflow Overview

Image Collector is a complete solution for collecting, augmenting, and preparing image datasets for computer vision models. The workflow consists of 4 main stages, each utilizing industry-standard techniques and models.

📸 Stage 1: Image Capture

Technology Stack:

  • Camera Interface: FFmpeg with AVFoundation (macOS) / V4L2 (Linux)
  • Streaming Protocol: MJPEG over HTTP
  • Frame Rate Control: Precision interval-based capture (30-180 frames/min)
  • Storage: Async parallel file I/O (50 concurrent saves)

Features:

  • Real-time preview with adjustable resolution (720p, 1080p)
  • Automated session capture with configurable rates
  • Live progress tracking and queue monitoring
  • USB/Network camera support

🎨 Stage 2: Data Augmentation

Standard Augmentation Techniques:

  • Geometric Transformations:
    • Rotation: -15° to +15° (simulate camera angle variations)
    • Zoom: 0.5x to 1.5x (object scale variation)
    • Horizontal Flip: Mirror augmentation
  • Color Augmentation:
    • Brightness adjustment (±30%)
    • Contrast & Saturation control
    • Grayscale conversion
  • Background Replacement:
    • Automatic segmentation using rembg (U-2-Net model)
    • Polygon mask extraction via OpenCV contours
    • Multi-background composition

🏪 Retail-Specific Augmentations:

  • Shelf Placement Variations: Simulate different shelf positions, stacking arrangements, and product orientation on retail shelves
  • Store Lighting Conditions: Replicate LED, fluorescent, and natural lighting found in retail environments with varying color temperatures
  • Product Occlusion: Simulate partial hiding by other products, hands, or shopping equipment to train robust detection
  • View Angles: Generate top-down (overhead cameras), eye-level, and below-eye-level perspectives for diverse camera placements
  • Distance Scale Variations: Create near, mid, and far-distance views to handle different shelf-to-camera distances
  • Glare & Reflections: Add realistic glare effects from store lighting and glass surfaces common in retail settings
  • Shopping Context: Include contextual elements like shopping carts, baskets, and hands to improve real-world accuracy

Models Used:

  • rembg: Background removal using U-2-Net architecture
  • OpenCV: Image processing and polygon simplification (Douglas-Peucker algorithm)
  • PIL/Pillow: Image manipulation and composition

⚙️ Stage 3: Dataset Generation

Generation Pipeline:

  • Batch Processing: FFmpeg-based parallel image generation
  • Format Support: JPEG output with configurable quality
  • Annotation: JSON metadata with bounding box coordinates
  • Dataset Structure: YOLO-compatible folder organization

Output Formats:

  • Training images with augmentations
  • Segmentation masks (PNG format)
  • Polygon annotations (JSON format)
  • Dataset manifest and statistics

📦 Stage 4: Version Management

Version Control Features:

  • Automatic versioning with timestamps
  • Dataset statistics tracking
  • Export formats: ZIP, TAR, direct download
  • Version comparison and rollback capability

🔧 Technical Specifications

Backend

  • Node.js + TypeScript
  • Fastify web framework
  • Async I/O with 50 parallel workers

Image Processing

  • FFmpeg for video capture
  • Python (rembg, OpenCV, PIL)
  • U-2-Net for segmentation

Performance

  • 160 frames/min capture rate
  • 20-30 images/sec save throughput
  • Real-time progress monitoring

Supported Models

  • YOLOv11 (detection)
  • U-2-Net (segmentation)
  • SAM (optional, advanced segmentation)

💡 Best Practices

  • Capture images at consistent intervals for uniform dataset
  • Use multiple backgrounds to improve model generalization
  • Apply varied augmentations to increase dataset diversity
  • Monitor queue status during high-speed capture sessions
  • Version your datasets before major changes
  • For Retail Models: Enable retail-specific augmentations (shelf placement, store lighting, occlusion) to improve real-world accuracy
  • Use version comparison tool to track improvements across dataset iterations
  • Export version metadata regularly for documentation and reproducibility
